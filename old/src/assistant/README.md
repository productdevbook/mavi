# assistant

A key an assistant can actually work with, good for a day.

**Who reaches it.** The panel, `people:view` to see what is out and
`people:write` to hand one over or take it back — a key is a way into the site,
so it asks what inviting somebody asks.

**Tables it owns.** None. A key is a session, on an account of its own.

**Its own account.** What an assistant did reads as an assistant in the bin and
in a post's author, and a key can be taken back without ending somebody's own
session. There is no password on that account and none is ever set: the only way
to be it is to hold a key somebody made.

**A day.** A key is pasted into somebody else's program and read by a model. It
will end up in a transcript, in a log, and possibly in a screenshot, and none of
those should still be a way in next week.

**What it may not do is a shorter list of grants**, not a promise: no settings,
because those hold other services' credentials; no accounts; and nothing deleted
for good, because those are the acts there is no way back from. The engine
refuses them the same way it refuses anybody.

**Named by something that is not the key.** The listing shows a fingerprint of
the hash, which is enough to tell two apart and not enough to be one, and taking
one back names it by that.

**Handing over is one call.** A key with no document is a string somebody has to
explain; a document with no key is what a site used to hand out.

## What it deliberately does not do

- No model of its own, no prompt, no key to anybody's inference API. This is
  what an assistant is given, not one that is run here.
- No wider reach on request. A key that could be talked into more than this list
  is not a shorter list.
