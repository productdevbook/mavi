# pages

What is wrong with a page, said before anybody reads it.

**Who reaches it.** The panel, with `content:view`: everything wrong across the
site, or everything wrong with one page.

**Tables it owns.** `page_issues`.

**Worked out when a page changes**, not when a screen asks. Computing this per
visit is a screen that reads every post to draw a badge, and the test counts the
queries that asking the whole site costs.

**A kind rather than a sentence.** `title.short`, `excerpt.missing`,
`body.image.unnamed`. The sentence belongs to whatever is showing it, in
whichever language it is being shown in — so nothing here is English.

**Fixing it stops it saying so.** What was wrong before is cleared and what is
wrong now is written, every time the page changes.

**The checks.** A title long enough to read and short enough to be shown whole;
a summary, and one that is not too long; a page with something on it; an
address that is not a paragraph; a link with words in it; a picture with words
for somebody who cannot see it.

**What it deliberately does not do.**

- No reading the built page. These are the source's problems; whether the built
  HTML has one heading or four is the theme's business and needs the build.
- No links checked against the world. A link that is dead today is not a page
  that is wrong.
- No score. A number out of a hundred is a thing people optimise instead of
  fixing what it counted.
